# AM Infinity .97：独立互操作协议笔记

来源：2026-10-14 读取官方公开页面 `https://ammaster.angrymiao.com/mouse` 的 `assets/index-32dd77b9.js`，对照本机 I/O Registry 描述符与实际收发结果。这里只记录互操作事实；源码为独立 Swift 实现，未嵌入官方 JS、Python 或固件。界面展示素材归属见 THIRD_PARTY_NOTICES.md。

## 实机接口

- VID `3725 / 0x0e8d`；接收器 PID `1795 / 0x0703`。
- 配置集合 Usage Page `0xff13`，Feature Report `0x14`。
- 包含 Report ID 的报告长度 62 字节：`14 | size | route | RACE bytes | zero padding`。
- 2.4G 鼠标路由 `0x80`；`0x00` 是接收器本地路由。
- 实测直接使用 `0x80` 读取成功，没有更改配对、link type 或固件。
- USB 本体 PID `2176 / 0x0880`、路由 `0x00` 来自官方脚本；已在 0.5.0 完成实机验证（见下文）。

## 报文

RACE 请求：`05 5a <payloadLength+2, LE16> <command, LE16> <payload>`。

回复观察到 `05 5b` 和 `05 5d`，其后同样为长度、命令、负载。成功负载首字节为 `00`。回复可能分片或混有通知，因此按路由过滤并重组、校验命令、长度与状态。不要只看到 USB 调用成功便认为硬件已应用。

| 命令 | 含义 | 参数 |
|---|---|---|
| `0x30c5` | 读 DPI | 无 |
| `0x30cf` | 读鼠标电量 | 无 |
| `0x30c9` | 读当前配置 | 无 |
| `0x30c4` | 写一档 DPI | 档位 index u8 + X LE16 + Y LE16 |
| `0x30c7` | 选择/刷新当前 DPI 档位 | index u8 |

实测 DPI 负载 35 字节：status、有效档数、当前 index、8 个 X LE16、8 个 Y LE16。写 DPI 不携带 RGB，因此不改灯光。若修改当前档位，按官方行为再发当前 index 使其生效；本轮物理写入验证仅覆盖非当前档位，当前档位刷新分支尚未实测。

实测电量回复：`00 00 43 ff 01 22 01`，第三字节 `0x43=67%`，第二字节未充电。短格式只读取 16 位百分比，充电状态未知；不把未知当作已证实状态。

## 边界

未探测未知写命令、未刷固件、未恢复出厂、未修改板载其他配置。没有解决所有固件/连接版本差异。现有设备断开或休眠超时会显式报错；不能保证所有固件支持该路由。

## 0.3.0 按键与版本查询

2026-10-14 对照同一官方公开客户端并实机确认：

| 命令 | 含义 | 参数 |
|---|---|---|
| `0x30c3` | 读取按键映射 | physical key ID u8 |
| `0x30c2` | 写入按键映射 | key ID + type + params |
| `0x1c07` | 固件版本（只读） | `00`；鼠标 route 0x80，接收器 route 0x00 |

映射回复为 status + key ID + type + params。1–7 分别为左、右、中、前侧、后侧、上滚、下滚。默认 type 为 1、2、3、4、5、12、13，参数为空。type 6 为快捷键：consumer usage LE16 + keyboard usage u8 + modifiers u8；修饰位 Ctrl=1、Shift=2、Alt=4、Command=8。后侧键 Cmd+C 实测写入 `[5,6,0,0,6,8]` 并读回。未知类型/宏按字节保留，不编辑宏；超过当前单包安全恢复长度的映射拒绝修改。

每次写入先读取全部 7 键及配置，检查草稿基线一致，原始事务原子落盘并同步，再只写目标键；读回全部映射必须精确一致。异常尝试恢复；未确认时保留 pending。至少保留一个左键。恢复限制同一个 HID 连接实例和板载配置，避免误写其他鼠标。

版本查询可能先返回单字节成功 ACK，随后才返回版本；ACK 不能当成完整版本。实测两端回复 `[0,0,6,118,49,46,56,46,52]`，ASCII 为 `v1.8.4`。

## 0.5.0 蓝牙与 USB 连接

2026-10-14 实机蓝牙 HID 身份：产品名 `AM Infinity .97`，Transport `Bluetooth Low Energy`，VID `0x0148`、PID `0`、主 Usage Page `0x0c`。该 HID 描述符只有标准输入功能，没有 USB 的 Feature Report 0x14；不能把 USB 报告直接发给它。

CoreBluetooth 通过已经连接的同名设备发现以下服务：

| 用途 | UUID |
|---|---|
| RACE 服务 | `5052494D-2DAB-0341-6972-6F6861424C45` |
| TX（withResponse 写请求） | `43484152-2DAB-3241-6972-6F6861424C45` |
| RX（notify 回复） | `43484152-2DAB-3141-6972-6F6861424C45` |
| 标准电量 | `180F` / `2A19` |

蓝牙发送原始 RACE 帧，没有 HID report ID、长度/route 外壳或补零。回复按 RACE 帧内长度重组通知分片。此服务及封包结构也与 [ERNW 原始研究，GATT Transport 一节](https://static.ernw.de/whitepaper/ERNW_White_Paper_74_1.0.pdf) 相符；这里只发送既有鼠标配置和版本命令白名单，未使用其他芯片命令。标准电量读取为 65%，RACE 电量也为 65%；App 使用 RACE 快照统一读取电量和 DPI。

蓝牙实测：当前 DPI 3400；第 1 档 400→450→400，全部 DPI 字节恢复一致；后侧键临时改为 Cmd+C，再恢复用户原有配置，全部 7 键读回一致；鼠标固件 1.8.4。测试通过与 App 相同的持久化事务服务执行。蓝牙不查询接收器固件。

USB 官方客户端身份包括 `0x0e8d:0x0880` 和 `0x35a1:0x0035`，使用本地路由 0x00；仅接受已知 Usage Page 0xff13 / 62 字节配置接口。实物 USB `0x0e8d:0x0880` 与接收器同时连接时，App 正确优先选择 USB；DPI 400→450→400 与后侧键临时映射/恢复全部读回一致，固件版本 1.8.4。另一组 `0x35a1:0x0035` 尚无对应实物验证。

连接策略：USB 优先，其次系统当前已连接的蓝牙鼠标，最后接收器；同级出现多个设备则拒绝选择。蓝牙不扫描、不发起系统配对；需要系统蓝牙权限。写入仍绑定同一个 IORegistry 连接实例与配置基线；切换连接不能用旧快照写到新接口。连接切换后清空旧撤销记录，保留磁盘备份。每两秒只检查本地接口变化，正常电量读取仍为每 30 秒。

App UI 验收：用户允许蓝牙权限后，USB→蓝牙自动切换成功；USB 和蓝牙界面分别完成后侧键“调度中心 → 拷贝 → 调度中心”，保存和撤销均确认全按键读回。未重置用户已有前/后侧键快捷键。


## 0.6.0 灯效（公开测试版）

官方客户端提供鼠标常亮、呼吸、霓虹，速度 1–10、最多 7 个 RGB 颜色；接收器提供常亮、呼吸、弧线、马赛克、极光、夜城、流动，速度 1–20、亮度 1–255，部分模式使用各自的色相/饱和度。

| 命令 | 含义 | 参数/回复 |
|---|---|---|
| `0x0a0c` | 读取灯效 NV | NV ID LE16 + 请求长度 LE16；返回 status + ID LE16 + 实际长度 LE16 + 数据 |
| `0x0a0d` | 保存动画 | 仅允许 NV `0x6200`；ID LE16 + 原始动画 |
| `0x30b3` | 鼠标灯效参数 | enabled、mode（0/1/2）、speed 三字节 |
| `0x30c0` | 常亮实时颜色 | `80 00 10 01 R G B` |
| `0x300e` / `0x300d` | 接收器灯效读 / 写 | 接收器本地 route 0；13 字节，无额外 status 前缀 |

鼠标参数 NV `0x600a` 为三字节；动画 NV `0x6200` 为 LED count=1 + RGB 数据长度 LE16 + 帧间隔 u8 + RGB 帧。原始字节必须完整备份，不能用 UI 中恢复出的颜色重建备份。当前先读取四字节动画头部，再按声明长度完整读取；校验前后头部一致。写入后的成功依据是完整读回，不是 HID 调用或 GATT ACK。

接收器 13 字节：enabled、mode、三组 hue BE16/saturation u8、speed+80、brightness。常亮、呼吸、流动分别使用第 1、2、3 组颜色，其他模式使用预置色。

验证范围：USB 三种鼠标效果、接收器自身七种效果、USB App 保存/撤销已通过；接收器到鼠标的常亮已通过，长动画完整读取仍超时。蓝牙三效果、七颜色最慢速度边界和 App 呼吸灯保存/撤销已通过。接收器的只读长度测试确认 48/128 字节可返回、256 字节超时；保持鼠标活动时仍可复现。当前将接收器鼠标 NV 请求和写入限制在 128 字节内，先读头部；超出范围提示改用蓝牙/USB，不继续发送长请求。生成精简动画时减少采样数、调整帧间隔以保留周期，若间隔超过 255 ms 则拒绝该速度/颜色组合。最终接收器实机复测中，三种精简鼠标动画及接收器自身七种效果均完成写入、完整读回和精确恢复；App 呼吸灯保存和撤销也通过。原始灯效已恢复，DPI 和全部按键映射未变，没有待恢复事务。验证的是持久化配置，不代表已做物理 LED 外观对照；该版本仍为公开测试版。
